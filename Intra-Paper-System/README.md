# Intra Paper System

An isolated, offline-first Java 21 futures and options research simulator. Its established bar runner handles one dated contract at a time, while a separate validated multi-instrument portfolio path provides diagnostic replay and artifact verification. Optional L1 quote execution uses caller-supplied local journals. The project is separate from the HFT 2 research notes and has no broker or network adapter.

## Built in this increment

- The [offline incident and recovery drill orchestrator](docs/OFFLINE-INCIDENT-DRILLS.md) runs strict synthetic scenarios through existing risk/replay components, enforces safe halt, exact reconciliation and scenario-authorized reset, and emits deterministic hashed PASS/FAIL/INCOMPLETE evidence. Nine fixtures cover feed loss, stale marks, uncertain orders, limit breaches, corrupted checkpoints, restart and unsafe resets. Synthetic drills do not count as G4 operating sessions or prove live recovery.
- Portfolio risk auditing reconciles terminal settlements, exact remaining basis, charge components, and fee-inclusive session losses. Still-open positions retain the original final-close quote time; stale marks or missing nonflat settlement charges produce INCOMPLETE. See [risk auditing](docs/PORTFOLIO-RISK-AUDIT.md) and its [settlement contract](docs/PORTFOLIO-RISK-AUDIT-SETTLEMENT.md).
- Registered portfolio evaluation binds settlement policy, targets, and event/cost hashes through parameter identity V2. Full-split artifacts exclude terminal holdout settlement financial payloads; development/validation-only artifacts include terminal validation settlements after full accounting verification. Final-bar metadata must match the actual checkpoint even when holdout financial fields are sealed. See [trial evaluation](docs/PORTFOLIO-TRIAL-EVALUATION.md).
- Strict UTF-8 CSV decoding rejects malformed provenance bytes while preserving valid Unicode, BOM/CRLF support, and exact original-byte hashes. The [settlement example](examples/portfolio-settlement/README.md) and [completion report](../research/systems/2026-11-05-portfolio-settlement-completion-report.md) record the final checks and the separately identified pre-commit JAR.
- Dedicated offline `PortfolioSettlementAuditCli` and `portfolio-settlement-audit.ps1` reconstruct completed portfolio runs and publish separate atomic settlement sidecars. Caller cash values support signed futures/options positions, exact final-mark adjustments, compatible dated settlement charges, and semantic/artifact verification. Replay outputs remain unchanged; exchange/broker source validation remains open. See [portfolio settlement audit](docs/PORTFOLIO-SETTLEMENT-AUDIT.md).
- JDK 21 command-line application with `validate`, `run`, run-artifact `verify` and `oms-recover`, quote-journal `journal-verify`, `quote-quality-report`, `quote-feature-export`, `quote-order-replay` and its artifact verifier, raw-capture `raw-capture-verify`, `feed-lifecycle-report`, `feed-capture-reconcile`, and deterministic `replay-verify` commands.
- Java API to import verified raw captures into normalized quote journals through caller-supplied offline decoders; the importer publishes only a fully verified journal and does not include a vendor adapter.
- Separate hash-chained feed-lifecycle journal records sanitized connection, authentication, subscription, heartbeat, disconnect, and reconnect facts. Its analyzer reconstructs state and counts invalid transitions. It does not connect to a feed or establish market-data completeness.
- `feed-capture-reconcile` verifies a feed-lifecycle journal and raw-capture journal, then matches captured message receive times against acknowledged subscription intervals by source, connection, and subscription ID. Its wall-clock tolerance is explicit; unmatched messages, empty intervals, and timeline anomalies are diagnostics, not a completeness certificate or vendor adapter.
- `raw-capture-clock-report` verifies and streams a raw journal, comparing each connection's wall-clock and monotonic elapsed-time deltas against a caller-supplied tolerance. It reports regressions and divergence without claiming UTC synchronization, source timestamps, feed completeness, or order-path latency.
- `run` can opt into `L1_FULL_SIZE_IOC` or `L1_PARTIAL_IOC` using a verified local quote journal. Both modes consume displayed top-of-book size by quote sequence/side and independently reconcile quote choice and price; partial mode fills only whole market lots and cancels the IOC remainder. Partial entry/exit basis, fees, position units, and checkpoint state are accounted for. Passive queues, deeper levels, and market impact remain unsupported. See [L1 strategy execution](docs/L1-STRATEGY-EXECUTION.md).
- Offline `QuoteOrderReplay` evaluates IOC market or marketable-limit intents at caller-supplied arrival latency against verified L1 quote history. Per intent it caps fills at displayed top-level size, emits full/partial/missed outcomes and OMS state transitions, and cancels IOC residuals. It does not deplete displayed size across intents, infer passive queue fills, calculate fees, submit broker orders, or provide a conservative fill lower bound; it is not wired into the bar strategy runner.
- `quote-order-replay` accepts a strict intent CSV, verifies its quote journal, indexes snapshots by source/instrument/receive time, processes intents in arrival order, and atomically publishes a content-addressed run folder. Its manifest records build identity, input hashes, quality thresholds, outcome counts, and result-file hash. `quote-order-replay-verify` checks the manifest identity and result hash. The batch consumes displayed quantity once per selected quote and side until another snapshot is selected. It still loads the complete quote history into memory; use only with journals that fit available memory.
- L1 feature API and streaming CSV exporter derive spread, midpoint, size-weighted microprice, and displayed-size imbalance from normalized quotes at explicit decision times. The snapshot-based L1 order-flow estimate requires consecutive local journal sequences, the same source, and eligible snapshots; no depth or queue claims are made.
- `EuropeanOptionPricer` and `Black76OptionPricer` compute European Black–Scholes–Merton spot-option and Black-76 futures-option values and Greeks from caller-supplied inputs. Outputs are per underlying unit; vega/rho are per percentage point and theta is per 365-day calendar day. Black-76 treats the supplied futures price as independent of the discount rate. Both pricers passed the supplied rounded R11 fixture set and QuantLib-Python 1.44 comparison; this validates formula implementation only, not market inputs or calibration to a market implied-volatility surface. The optional replay sidecar reports model values but does not use them in fills or accounting.
- `portfolio-stress` aggregates signed option/futures model delta and option gamma/vega/theta/rho alongside full-revaluation shock P&L; it fails when the downward volatility shock makes any option IV non-positive. Inputs remain caller supplied, and the report is not account-connected or an exchange-margin calculation.
- Option-premium replay can opt into an exact-close-time caller-input BSM/Black-76 valuation sidecar. It requires one model-input row per bar, hashes the source into run identity, and emits a separately verified `option-valuation.csv` with per-unit and close-of-bar position-scaled Greeks; model values do not affect fills or accounting P&L.
- Option replay can also opt into a caller-limited four-scenario pre-entry stress-loss check using the prior decision bar's valuation inputs. Its decision is recorded and independently recomputed by the run risk reconciler; it is an in-process simulator control, not a separate risk process or exchange-margin calculation.
- `ToyLimitOrderBook` is an offline API for deterministic price/time matching, partial fills, cancellation, and bounded-by-book market IOC sweeps using integer ticks and units. It has no NSE-specific rules, price protection, latency, fees, hidden liquidity, auction behavior, or queue calibration, and is not wired into the bar strategy runner. See [the toy order-book assumptions](docs/TOY-ORDERBOOK.md).
- `riskgateway.RiskGateway` is an isolated proposal gate and signed-position/reservation ledger with caller-supplied marks and margin inputs. `DurableRiskGateway` publishes changes after forced journal append, disables the instance after persistence uncertainty, and requires a separately retained configuration-bound checkpoint for restart. The two-argument constructor creates new journals only; rejected decisions remain process-local. The dedicated `test-risk-gateway.ps1` runner passed 447 offline checks in 13 groups, and the subprocess harness passed 728 checks across 308 child JVMs and 24 forced terminations on Windows/NTFS. See [operating notes and migration](docs/INDEPENDENT-RISK-GATEWAY.md), the [durability report](../research/systems/2026-11-05-risk-gateway-durability-verification.md), and the [process-recovery report](../research/systems/2026-11-06-risk-gateway-process-recovery-verification.md). The package has no broker/network route; trusted checkpoint storage, account reconciliation and power-loss verification remain open.
- `CallAuctionEngine` provides a separate single-price clearing and matching primitive with explicit no-equilibrium behavior; it is not assigned to historical sessions or wired into replay until effective-dated exchange rules are verified. See [the call-auction assumptions](docs/CALL-AUCTION.md).
- Strict normalized-candle CSV parsing, monotonic and same-session interval-spacing checks, OHLC/tick validation, and explicit timestamp-role handling.
- `SynchronizedBarFrameBuilder` prepares exact-timestamp frames from multiple prevalidated dated futures/option series. It rejects missing/mismatched timestamps, duplicate or reordered bars, changed contract identity, and incompatible interval/timestamp roles; it never forward-fills. The separate portfolio accounting component below consumes these frames, but they are not wired into the existing single-contract runner. See [the multi-instrument frame contract](docs/MULTI-INSTRUMENT-BAR-FRAMES.md).
- `PortfolioAccountingLedger` is a separate offline signed-position ledger for synchronized multi-contract frames and caller-supplied simulated executions. It computes realized and unrealized gross P&L, caller-supplied fees, and net P&L without future-close marks for BAR_START data. It does not create fills, infer costs/margin, or connect to an order route. Explicit final-session settlement releases exact remaining basis and accounts for separately supplied charges. See [the portfolio accounting contract](docs/PORTFOLIO-ACCOUNTING.md).
- `PortfolioReplayEngine` runs a strategy against an immutable synchronized-frame history, executes target changes only at a later BAR_START open through a caller-supplied fill model, and records opening/closing portfolio marks. It requires exact signed-lot targets and per-instrument caller limits, explicit session-boundary policies, and keeps results diagnostic-only. An optional caller-sourced effective-dated CSV calculates and audits brokerage, exchange/IPFT/SEBI charges, STT, stamp duty, and GST with explicit bases; no market or tax rate is built in. Separate caller-sourced final-session settlement and exercise charges are supported; see [the settlement contract](docs/PORTFOLIO-SETTLEMENT.md). See [the portfolio replay contract](docs/PORTFOLIO-REPLAY-ENGINE.md).
- `ValidatedPortfolioDataset` loads multiple one-contract CSV/config pairs through the existing full `ValidatedDataset` checks before exact-time synchronization. It retains per-contract provenance and produces a canonical portfolio-input hash; it never forward-fills. `PortfolioReplayEngine` can accept this validated input directly and includes the dataset and optional cost-schedule provenance in its replay identity. `portfolio-run` exposes a bounded long-only per-contract SMA diagnostic strategy and next-open full-IOC fill assumption; it publishes dataset/decision/order/execution/itemized-fee/settlement/settlement-cost/equity CSVs into an atomic content-addressed folder. `portfolio-replay-verify` checks its manifest hashes, fee rows, reruns the same inputs/build, and byte-compares regenerated outputs. These commands remain diagnostic-only and do not connect to a broker or risk gateway.
- `PortfolioRiskAuditCli` is a separate post-run audit tool for verified multi-instrument replays. It independently reconstructs signed positions, exposures, gross notional, fee-inclusive P&L, and caller-supplied margin-proxy totals at bar-open, bar-close, and terminal settlement checkpoints, then reconciles its calculations to the saved replay. Four strict dated risk-input CSVs provide limits, margin proxies, source references, and portfolio budgets. Version 2 reports add separate settlement reconciliation and itemized charges with explicit PASS/BREACH/INCOMPLETE status. Invoke it through `portfolio-risk-audit.ps1`; it does not gate replay, cover intrabar risk, calculate SPAN/ELM, or connect to an account.
- `PortfolioTrialEvaluationAnalyzer` and the dedicated `portfolio-trial-evaluate.ps1` entrypoint evaluate complete registered portfolio trial families from verified artifacts. A strict catalog binds registration/run/split/parameter identities and explicit starting capital; aggregate DEVELOPMENT/VALIDATION session returns feed the shared Sharpe, DSR sensitivity, and chronological-block CSCV definitions. Optional outcome history adds verified provenance and counts. Every result remains performance-ineligible. See [the portfolio evaluation guide](docs/PORTFOLIO-TRIAL-EVALUATION.md).
- Required open-session calendar and effective-dated market-rule registry. Each open date must resolve by regime ID, effective date, exchange/segment/contract kind, source reference, timezone, session window, lot size, and tick size. Session/run artifacts retain the applied rules and registry hash. Source verification labels remain caller assertions. A run is restricted to one dated futures or single-option contract; expiry stitching and index-to-futures substitution are rejected.
- A reusable strategy API receives immutable history ending at the decision candle, so strategy code cannot read future bars through the replay interface. The built-in long-only SMA crossover is a plumbing harness; signals can execute at the next eligible bar open or, when explicitly configured, against a verified L1 quote snapshot after caller-supplied latency.
- One strategy-audit row per candle, with strategy diagnostics and warm-up status recorded.
- Fixed adverse tick slippage, explicit fee inputs, position/notional caps, and a per-session loss halt. These settings are recorded in each run.
- A configurable minimum time between new BUY intents; exits remain allowed, entry completion is limited to the original unexited target, and increases beyond that target or after an exit are rejected. The order/position ledgers are independently reconciled.
- Venue-neutral OMS state transitions, pending/unknown residual-unit reservation rules, and execution-ID idempotency primitives; the bar simulator currently exercises immediate local full-fill paths only.
- Optional effective-dated BUY/SELL execution cost schedule, contract-kind-aware itemized fee schedule, and source-attributed expiry settlement cost schedule. Executed charges are auditable in `fee-breakdowns.csv`, exercise charges in `settlement-charges.csv`, and additional caller-supplied settlement lines in `settlement-cost-lines.csv`.
- Local simulated order lifecycle, fills, completed trades, marked equity curve, run summary, input hashes, and output hashes.
- The built-in deterministic SMA replay checkpoints every 250 bars by default to `.checkpoints/<run-id>` under the run root. Re-running the exact same bars/config/build resumes from the last checkpoint in the verified chain; set `recovery.checkpoint_interval_bars=0` to disable it. A damaged chain fails closed. Checkpoints are cleared only after the complete run folder is published. Custom Java strategies must explicitly declare deterministic checkpoint support before using this recovery path.
- Input CSV hashes are computed from the exact byte streams consumed by their parsers; the run-properties hash is computed from the same byte snapshot used to parse its settings.
- Content-addressed run IDs include input, configuration, build, and strategy ID/parameter hashes; artifacts are written to a sibling staging directory and published with a same-volume atomic move after all files and hashes are complete. Sidecar OS locks protect active staging writes, and a later write removes only recognized abandoned staging directories whose lock is available. Results default outside the repository under `%LOCALAPPDATA%\Intra-Paper-System\runs`.

The bundled example is synthetic. Reports are always classified as `SYNTHETIC_PLUMBING_ONLY` or `REPLAY_DIAGNOSTIC_ONLY`, and `performance_claim_eligible` is always `false` in this build.

## Build and run

The [Windows Java 21 CI workflow](docs/WINDOWS-JAVA21-CI.md) runs twelve selected offline PowerShell runners, builds the production JAR, runs packaged daily operations and dataset permission checks, tests standalone and packaged multi-record permission coverage, runs the incident-drill acceptance suite against its standalone and production JARs, and verifies that the JAR manifest matches the checkout. It
pins Microsoft JDK 21.0.13.0.2 and retains concise logs and the verified JAR for
14 days. The complete test list and local reproduction commands are in the guide.

The [dataset permission preflight](docs/DATASET-INTENDED-USE-PREFLIGHT.md) checks declared evidence against intended use; ALLOWED is not legal approval. The [multi-record permission coverage checker](docs/DATA-PERMISSION-COVERAGE.md) reports scope cells and record conflicts. Both operate on caller-supplied declarations, do not grant permission, and leave G2 open.

The [daily operations evidence checker](docs/DAILY-OPS-EVIDENCE.md) validates a
caller-prepared local session bundle and reports PASS, FAIL, or INCOMPLETE across
pre-session checks, input freshness/coverage, risk events, artifact identity,
settlement/costs, closing reconciliation, and operator records. Nine synthetic
fixtures exercise the schema. Reports remain caller-supplied diagnostics, missing
evidence stays unknown, and G4 remains open.

Requires a JDK 21 installation. The build uses `JAVA_HOME` explicitly, embeds the Git commit only when the checkout is clean, marks dirty builds `unknown-dirty`, and writes compiler output outside the OneDrive project by default. Non-synthetic runs require a full commit ID, so a dirty-build JAR cannot run non-synthetic data.

```powershell
$env:JAVA_HOME = 'C:\path\to\jdk-21'
.\build.ps1
$jar = Join-Path $env:LOCALAPPDATA 'Intra-Paper-System\build\intra-paper-system.jar'
$java = Join-Path $env:JAVA_HOME 'bin\java.exe'
& $java -jar $jar validate .\examples\synthetic-futures-bars.csv .\examples\synthetic-run.properties
& $java -jar $jar run .\examples\synthetic-futures-bars.csv .\examples\synthetic-run.properties
& $java -jar $jar portfolio-run .\portfolio-inputs.csv .\portfolio.properties (Join-Path $env:LOCALAPPDATA 'Intra-Paper-System\portfolio-runs')
```

The multi-contract manifest and strict `portfolio.properties` schema are documented in [the portfolio replay contract](docs/PORTFOLIO-REPLAY-ENGINE.md). Use `portfolio-replay-verify <portfolio-inputs.csv> <portfolio.properties> <run-folder>` to rebuild and byte-compare a prior result under the same build and inputs.

Use `INTRA_PAPER_RUNS_DIR` to choose another local output directory. A repeated identical run uses the same content ID and will fail rather than overwrite existing artifacts. The `run` command resumes a deterministic built-in SMA replay from its latest checkpoint in the verified chain when the same inputs, configuration, and build are used. The `verify` command recomputes twelve output-ledger SHA-256 hashes from current manifests; it also accepts prior nine-, ten-, and eleven-output manifests. It does not verify source rights or re-hash input files. `oms-recover` verifies the full manifest before reconstructing completed-run OMS order states, deduplicated executions, reservations, and final position from saved ledgers. It does not restore broker state. `journal-verify` scans a quote journal and validates its framing, canonical encoding, sequence ordering, and SHA-256 hash chain without connecting to a data source. `quote-quality-report` performs the same full integrity scan while reporting event-time and structural quote flags using explicit caller-supplied freshness thresholds. `quote-feature-export` writes sequence-aware L1 metrics from a fully verified journal with atomic no-overwrite publication. `feed-lifecycle-report` verifies a `.flj` journal and reports event counts, reconstructed connection states, unresolved subscriptions, and invalid transitions. `feed-capture-reconcile` separately verifies both journals and compares each raw message source/connection/subscription and receive time with acknowledged lifecycle windows using caller-supplied wall-clock tolerance. It reports unmatched messages, empty intervals, anomalies, and hashes, but does not map decoded instruments, prove completeness, establish data rights, or correct clock errors. Flag counts can overlap, and quote reports/feature exports do not determine feed completeness, source semantics, data rights, or whether a threshold is appropriate. `replay-verify` rebuilds all run artifacts from supplied bars and configuration in a temporary folder and requires a byte-for-byte match with the saved ledgers and manifest.

See [the operating guide](docs/OPERATING-GUIDE.md) for the input contract and run files.

The `statistical-evaluate` command reports development/validation session-return Sharpe, an independent-normal DSR approximation, and chronological-block CSCV PBO for fully preregistered, artifact-verified trials. It excludes holdout P&L from statistical calculations and always marks results performance-ineligible. Portfolio evaluation schema V3 adds a separate content-pinned Sharpe HAC standard error and autocorrelation diagnostics. It includes no-trade sessions, reports INCOMPLETE below 60 sessions, leaves DSR/PBO unchanged, and emits no interval or profitability probability. Synthetic qualification is limited to three frozen processes; independent preregistration is unverified and prior exposure unknown. See the [HAC protocol](docs/PORTFOLIO-SHARPE-HAC-PROTOCOL.md), [method audit](../research/systems/2026-11-04-dsr-pbo-audit.md), and [operating guide](docs/OPERATING-GUIDE.md).

## Scope and limitations

- The established bar runner handles one dated futures or listed option premium series per run and uses a long-only SMA harness. A separate validated portfolio CLI can replay multiple synchronized futures/options contracts with a long-only per-instrument SMA target, a next-open full-fill assumption, and an optional caller-sourced dated execution-cost schedule. Portfolio expiry settlement uses explicit per-contract events and a separate dated cost contract, with caller-declared rounding and independent artifact reconciliation. Long-only expiry settlement in the single-contract runner is supported only from an explicit source-attributed input row. A component cost schedule can model option exercise STT and SEBI turnover using the applicable rate row and sourced turnover basis. An optional settlement schedule adds caller-sourced effective-dated fixed, per-unit, or basis-point charge lines with explicit GST-on-charge selection; these inputs do not establish a complete or verified account tariff. Integrated L1 execution requires caller-supplied latency and quality thresholds; full-size mode cancels when displayed quantity is insufficient, while partial mode caps fills at visible top-of-book size rounded down to whole lots and cancels the IOC remainder. Neither mode models passive queues, depth, market impact, or broker orders. Option model values and Greeks are diagnostics only; independent account-level portfolio risk, stop orders, and exchange matching remain unmodeled.
- No live quotes, API credentials, broker connectivity, or live order route. Simulated acknowledgements are local ledger events.
- The configurable per-order, per-unit, notional-basis-point, and tick-slippage cost model is diagnostic, not a current exchange/broker cost schedule. The entry gate accepts either a fixed margin proxy or a source-attributed effective-dated per-contract margin input; neither is an exchange SPAN/ELM calculation or contract-sizing advice.
- The simulator validates supplied regular-session boundaries against the dated caller rule registry, but does not implement exchange matching, pre-open auction execution, market-on-close behavior, or automatic rule sourcing. Pre-open, expiry, ELM, and calendar-spread fields are recorded as dated metadata and do not drive order or margin mechanics. `ALLOW_OVERNIGHT` permits cross-session/end-of-data positions; `REQUIRE_FLAT` fails when one remains; `AUTO_FLATTEN_SESSION_END` suppresses new entries at the penultimate bar close and schedules an open-position exit for the final bar open. The supplied calendar must be reviewed. This is a bar-model assumption, not a guaranteed real-market close.
- Cross-session pending orders are disabled by default and cannot be combined with either flat-at-session-end policy. Automatic flattening fails closed if the final bar is reached with a position still open.
- The sample strategy and all synthetic inputs are plumbing examples, not trading recommendations or evidence of an edge. Current data rights, costs, operating limits, and G0/G1/G2 evidence remain open.
- There is no unified automated test suite. Focused Java 21 PowerShell runners cover selected components, including synchronized multi-instrument frames and portfolio accounting; the synthetic sample replay exercises plumbing only and broader behavior remains unvalidated.

Private data, raw-capture journals (`.rawcap`, `.rawcapture`, `.raw`), feed-lifecycle journals (`.flj`), quote journals (`.qj`, `.qjr`), standard run artifacts, and `quote-replay-runs/` are excluded from Git. Never put broker credentials, account identifiers, private budgets, raw server messages, or licensed market rows in this repository. The ignore patterns are convenience safeguards, not access controls; confirm `git status` before committing data files.
