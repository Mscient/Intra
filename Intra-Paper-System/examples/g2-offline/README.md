# G2 synthetic golden contract

`golden.raw` is independently laid out, not generated by the Java capture encoder. Its v1 header is `INTRARAW` plus big-endian version 1. The sole 49-byte record has schema 1, source `S`, connection `C`, subscription `U`, absent upstream sequence, epoch UTC receive time, synthetic monotonic value 7, and five opaque payload bytes `00 0a ff 80 7f`. Its chain is SHA-256 over 32 zero bytes followed by the record; the frame contains its big-endian length and chain digest. The complete 97-byte file's SHA-256 is in `golden.raw.sha256`.

These bytes contain no market/account information. The task authorizes creating and retaining this synthetic test fixture in Git. They establish framing and byte preservation only. The test generates truncation, corruption, conflicting-ID, chronology, oversize, and rejected-import fixtures under its separately reported evidence directory; original raw input files are never repaired.

`test-g2-reproducibility.ps1` freezes the existing fictional 30-bar contract and generates a synthetic raw quote/lifecycle journal. Each quote is an explicitly fictional one-unit bid/ask around the bar open; this is plumbing, not a market observation or calibration. The frozen capture contract records process/capture identity, decoder revision and timestamp roles. Two isolated child JVM settings independently decode it and run the existing bar/L1 simulators; complete run artifacts and synthetic quality records are byte-compared. No passive queue model is supplied.
