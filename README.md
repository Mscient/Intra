# Nifty Intraday Research Project

This repository tracks research for a cost-aware Nifty intraday paper-trading system in India. The initial brief sets the constraints: own account, Nifty first, Python/research-first, no paid tick feed at the outset, and a 90-day paper-system target. The user has selected Angel One SmartAPI; documented capabilities and limits are in the [instrument/data matrix](research/systems/INSTRUMENT-DATA-CAPABILITY-MATRIX.md). The isolated `Intra-Paper-System/` subproject builds with Java 21 and contains an offline dated-derivative CSV replay simulator for one futures contract or one option premium series at a time, with a local simulated OMS, explicit risk/cost inputs, and hashed run artifacts. The [Windows Java 21 CI workflow](Intra-Paper-System/docs/WINDOWS-JAVA21-CI.md) runs nine selected offline suites, builds and verifies the production JAR, and tests the packaged daily-operations checker. It has no broker adapter or live order route; bundled examples are synthetic and no account credentials or licensed market data were used. The simulator offers a configurable session-end exit using a final-bar-open assumption and explicit source-attributed long-only expiry settlement inputs. Componentized option-exercise STT and SEBI turnover fees and dated source-attributed per-contract margin inputs are supported; the latter are not a SPAN/ELM calculator. Other settlement charges remain caller-supplied. European BSM and Black-76 pricers passed the supplied rounded R11 references and an independent QuantLib 1.44 cross-check; market-input validation, use in accounting, and account-connected risk remain open. The optional caller-limited pre-entry stress gate uses prior decision-bar inputs and is not an account risk service. Volatility surfaces and validated market assumptions remain open. Earlier session records describe a separate Python engine, which is not a port of this Java implementation. See the [paper-system roadmap](research/systems/PAPER-TRADING-BACKTESTING-ROADMAP.md) and [implementation tracker](research/systems/IMPLEMENTATION-TRACKER.md) for current scope and gates.

The portfolio replay supports caller-sourced final-session settlement of signed futures/options positions, exact residual-basis reconciliation, dated settlement/exercise charges with explicit rounding, and v3 artifact/deterministic verification. Strict UTF-8 parsing rejects malformed provenance bytes. The [risk audit](Intra-Paper-System/docs/PORTFOLIO-RISK-AUDIT.md) reconciles settlement checkpoints, charges, residual exposures, and session losses. [Registered evaluation](Intra-Paper-System/docs/PORTFOLIO-TRIAL-EVALUATION.md) binds settlement inputs and supports a development/validation prefix while preserving holdout financial exclusion. Dataset final-close timestamps must match the actual final bar checkpoint. See the [settlement example](Intra-Paper-System/examples/portfolio-settlement/README.md) and [completion report](research/systems/2026-11-05-portfolio-settlement-completion-report.md) for commands, verification counts, and the exact pre-commit JAR hash. These results remain diagnostic-only.

The reports translate book material and lawful public-source evidence into pre-build requirements. They distinguish publisher descriptions and previews from complete-book reading, and they do not claim that any strategy is profitable or ready for live trading.

## Source and text policy

Use publisher pages, authorized previews, library access, and public-domain or openly licensed works. Do not download or commit pirated scans or reproduce complete copyrighted books. Prefer original summaries with citations. If complete text requires a subscription or library login, record that access status and continue with lawful public material until authorized access is available.
