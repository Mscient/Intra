# DR-02 — SmartAPI capability, schema, limits and rights

Researcher: Codex, API/data assignment. Date/access date: **2026-11-05**, Asia/Kolkata. Scope: public SmartAPI documentation, official Python SDK and current offline Java importer/decoder. **Research candidates only; independent source review and account-specific inputs outstanding.**

## Executive finding

Public MarketData, RateLimit and FAQ retrieval returned an unauthorized page. The official SDK confirms interface code exists, but cannot establish server availability, current quotas, replay promises, data rights or account permission. A material conflict exists between the older project's 30-second WebSocket heartbeat statement and the SDK's 10-second setting. The current decoder/importer implement a narrow saved-input contract; their successful validation would not resolve source semantics. No network adapter or production setting is introduced.

Their scales, timestamp epochs, dummy/unused status and authoritative types are **not promoted**. In particular, SDK OI-change parsing is not permission to infer a percentage unit. Existing docs' “received time” dummy claim and unavailable index sequence remain un-revalidated. Preserve raw bytes; do not interpret arbitrary field values as local receive time.

A transport reconnect and SDK resubscribe do not imply replay, broker subscription acknowledgement, or first valid instrument quote. Exact error/status variants remain unknown.

Expired-contract history, total historical range, empty-minute omission, label meaning, timestamp timezone policy, final-bar handling, OI/volume units, correction schedule and product-specific differences require a current official response or versioned specification. A5's “expired F&O unavailable” is a useful blocking lead, **not a current verified categorical service fact**. No index candle becomes executable NFO data; DR-03 addresses the reported gap.

## Order state, rights and sandbox — questions 5–7

**Proposed semantic contract (INFERENCE):** retain separate request ID, acknowledgement/order ID, broker/exchange acceptance, working status, unique execution/trade ID, cumulative/last executed quantity, pending cancellation, cancellation confirmation, rejection and final reconciliation snapshot. A cancel request cannot release reservations; fills while cancel is pending still count. Unknown/unmapped status remains `UNKNOWN` and blocks increased risk. A4 forwards messages without supplying a full dictionary, so AB codes and JSON field mappings are deliberately not invented. Reconcile permitted order/trade/position snapshots with their independent as-of times and correction lineage; neither an HTTP success nor receipt of one update proves finality or complete history. DR-11/13 own recovery/reservation details.

Rights by layer: **exchange policy documented** (A7); **Angel product contract unknown**; **owner account/app permissions unknown**; local retention/deletion/backups/derived outputs/display/sharing/redistribution **unknown**. Free API charges, a public SDK license, successful prior login or static-IP setup is not a market-data license. DR-04 records additional website restrictions. No evidence establishes a current broker sandbox/paper environment. A commented UAT address in SDK source is not a publicly authorized sandbox. Keep local offline simulation distinct from broker paper execution.
