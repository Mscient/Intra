# Durable risk gateway facade

- **Date:** 2026-11-05 (Asia/Kolkata)
- **Objective:** Make the local risk gateway event journal persist accepted state changes before reporting success, while keeping the work offline and separate from simulator and broker paths.
- **Sources consulted:** `Intra-Paper-System/README.md`; `Intra-Paper-System/docs/INDEPENDENT-RISK-GATEWAY.md`; `Intra-Paper-System/IMPLEMENTATION-TRACKER.md`; `SESSION_PROTOCOL.md`; existing `RiskGateway` and `RiskGatewayJournal` implementation and recovery behavior.
- **Work completed:** Added `DurableRiskGateway`, which holds a process-lifetime exclusive lock, restores from the verified journal, persists accepted proposals and applied events before returning, and attempts journal-based state reconstruction after a write/application failure. If recovery fails, the facade is unavailable. Documented that rejected decisions are process-local and that concurrent direct use of the lower-level journal API can bypass the facade lock. Updated the implementation tracker.

- **Access and safety limits:** No broker, account, network, or live-order access was used. The facade is a single-process local writer, not an independently isolated service; journal events are unauthenticated, the lower-level append API can bypass the facade lock, and no external execution stream or account reconciliation is connected.
